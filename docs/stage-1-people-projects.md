# Stage 1 — People & Projects

- Статус: **завершён**
- Product Vision: V1
- Предыдущий этап: Stage 0 — Foundation

## Цель этапа

Создать стабильные сущности людей и проектов до появления composer. Будущие упоминания должны ссылаться на неизменяемые IDs, а переименование или архивирование не должно разрушать накопленный контекст.

## Пользовательские возможности

- Переключение между справочниками людей и проектов.
- Создание человека с отображаемым именем и уникальным alias.
- Создание проекта с названием и уникальным slug.
- Редактирование имён, aliases, названий и slugs.
- Архивация с подтверждением и последующее восстановление.
- Отдельный режим показа архивных записей.
- Empty, loading и error states.
- Адаптивная компоновка для desktop и tablet.

## Правила домена

- Person и Project получают UUID при создании.
- Alias и slug нормализуются в lowercase и хранятся без `@` или `#`.
- Alias человека поддерживает латинские буквы, цифры, `.`, `_` и `-`; значение по умолчанию генерируется из отображаемого имени заменой пробелов на точки: `Alex Morgan` → `alex.morgan`.
- Slug проекта поддерживает латинские буквы, цифры, `_` и `-`; значение по умолчанию генерируется заменой пробелов на `_`: `Content Editing Form` → `content_editing_form`.
- Автогенерация прекращает перезаписывать значение после ручного редактирования поля.
- Уникальность проверяется базой данных и не зависит от регистра благодаря нормализации.
- Архивирование не удаляет сущность и не меняет её ID.
- Архивная запись скрывается из активного списка, но доступна в режиме «Показывать архив».

## Реализация

- API: `GET/POST /api/people`, `PATCH /api/people/:id`.
- API: `GET/POST /api/projects`, `PATCH /api/projects/:id`.
- D1/SQLite tables: `people`, `projects`.
- Уникальные индексы: `idx_people_alias_unique`, `idx_projects_slug_unique`.
- Migration: `drizzle/0000_nostalgic_hulk.sql`.
- Runtime schema initialization делает локальный preview воспроизводимым; deployment migration остаётся каноническим способом подготовки hosted DB.

## Критерии приёмки

- Два человека с разными aliases успешно создаются.
- Повтор alias в другом регистре возвращает HTTP 409 и понятную ошибку.
- Проект создаётся и сохраняется после перезагрузки страницы.
- Переименование сохраняет ID сущности.
- Архивная запись исчезает из active list и возвращается при включении архива.
- Восстановление переводит запись обратно в active state.
- Typecheck, lint, unit tests и deployment build проходят.

## Проверено

- Нормализация `@Alias` / `#Slug` и правила допустимых символов покрыты unit-тестами.
- API round-trip проверен для create, edit, archive, active filtering и restore.
- Case-insensitive collision проверен запросом с HTTP 409.
- Миграция с таблицами и уникальными индексами сгенерирована и проверена.

## Не входит

- Команды и membership.
- Импорт из Slack или Jira.
- Composer, log entries и mentions внутри записей.
- Удаление людей или проектов.
- Аутентификация приложения и multi-user access.
